# 世慧屋 · 微信小程序产品说明

**产品名称**：世慧屋（微信小程序）
**文档版本**：v1.4.1
**编写日期**：2026 年 11 月

***

## 一、产品定位与要解决的问题

### 1.1 一句话介绍

世慧屋人物数据是一个以「人」为入口的中国历史数据工具：查一个人，能看到他的关系网络、生平年表与足迹地图；查一个年份，能看到同一年里谁登场、谁在场、谁离场。

### 1.2 产品定位

不是百科词条的搬运，也不是学术数据库的移动端翻版，而是把中国历史人物数据整理成几种可以直接操作的「看法」：

- **按人看**：人物档案、关系图谱、世系、年表、足迹，五个面看同一个人。
- **按时间看**：年份查询、大事年表、朝代时间轴、历代帝王，四个工具对应四种时间粒度。
- **按关系看**：六度空间找两个人之间的最短关系路径；双人生命线把两个人放进同一条时间轴。
- **按场景看**：平行时空对照同年中土与世界；「这一年，谁在场」把一年拆成登场、在场、离场三幕。
- **按名物看**：职官别名、地名古今对照；节日文化按月展开。
- **按阅读看**：文章专题 5 个、特别专题 4 个，专题内可读长文，文章中关联的人物可直接跳转档案。

产品形态为微信原生小程序，共 12 个主包页面、30 个分包页面（合计 42 个页面），另有配套的 Node.js 服务端与 SQLite 数据库。

### 1.3 要解决的问题

1. **人物信息散在词条里，关系读不出来。** 百科里「某某之子」「某某门生」写在段落中，读者很难一眼看清一个人的家庭、师承、同僚、敌对关系。本产品把关系抽取成结构化边，用图谱与列表两种方式呈现，并支持从一个节点继续往下走。
2. **纪年工具与人物、事件是割裂的。** 查「祥兴二年是哪一年」通常要用万年历或换算网站，查完还要另找这一年发生了什么。本产品把公元、年号、干支、伊斯兰历、佛历、民国纪年、日本年号七套纪年放在一次查询里，并把年份直接接到大事年表与平行时空。
3. **跨人物、跨朝代的比较缺少轻量工具。** 想知道苏轼和张居正隔几个人、李白和杜甫有多少年同在一世、1644 年中土与世界分别发生了什么，通常要靠人工翻书。本产品提供六度空间、双人生命线与平行时空三个专用页面。
4. **历史数据产品容易「看起来全，实际空」。** 本产品对缺字段的条目统一标「待补」，对无法确证的关系或生卒列入待考清单，不用推测填空；数据口径与修正记录留在仓库文档中，可追溯。

## 二、目标用户与典型使用场景

### 2.1 目标用户

| 用户类型          | 主要需求                 | 产品对应能力                     |
| ------------- | -------------------- | -------------------------- |
| 历史爱好者与普通读者    | 读史时随手查人、看关系、看年表      | 首页搜索、人物详情、关系图谱、大事年表        |
| 中学生、大学生与历史教师  | 建立时间感、理解人物关系、做课堂素材   | 年份查询、朝代时间轴、历代帝王、平行时空、双人生命线 |
| 内容创作者与编辑      | 快速核对人物生卒、关系、同年事件，找选题 | 人物档案、六度空间、平行时空、节日文化、文章专题   |
| 文旅、展陈与地方文化工作者 | 查人物足迹、古今地名、地方节庆      | 足迹地图、地名查询、节日文化             |
| 家谱与地方史爱好者     | 看世系上下几代、跨姓氏关系        | 世系页、关系图谱、六度空间              |

### 2.2 典型使用场景

1. **读到一个不熟的人。** 在首页输入「张居正」，从候选里点选，进入档案看生平与基础信息；切到「关系」看图谱，点「万历」继续看皇帝档案；切到「年表」按阶段看他一生的关键事件。
2. **写稿需要同年对照。** 打开「平行时空」，选年份 1644，左列看中土编年，右列看域外同期人物与事件；点「世界地图」换成地理分布；再进「这一年，谁在场」，分登场、在场、离场三幕看名单。
3. **课堂上讲两个人的交集。** 从人物详情年表顶部的「双人生命线」入口选另一个人，看双轨年表标出的共存区间、年龄差与晚走年数，或切到三段人生：只有他、同在一世、只剩他。
4. **查一个年号。** 在「年份查询」输入「祥兴二年」，一次得到年号纪年、干支、公元、伊斯兰历、佛历、民国纪年与日本年号；输入朝代名则先给开国、鼎盛、亡国三个参照年。
5. **做一条研学或旅行路线。** 在人物详情进入「足迹」，按时间轴逐站看事件卡，或一次铺开全部站点，在地图上连线看这个人一生到过哪里。
6. **春节前做节日选题。** 打开「节日文化」，按公历月份展开，或切到节令、民俗、民族、地方四类单独筛选，查节日起源与习俗。

## 三、核心功能逐项说明

### 3.1 首页：人物查询入口

- **搜索**：输入人物姓名，联想列表实时返回候选；点选候选才算选中。搜索框左侧可切换「全部 / 帝王 / 非帝王」，该筛选只在有关键词时生效，无关键词时置灰。
- **人物卡片流**：首屏随机取 20 位人物卡片，展示头像、姓名、生卒年与一句简介；卡片可拖拽浏览，网络失败时使用本地缓存兜底，不出现空白首屏。
- **快速查询四宫格**：年份查询、大事年表、朝代时间轴、历代帝王四个入口，点击直接进入对应工具。
- **特别专题入口**：首页提供特别专题入口，进入 4 个独立专题站。
- **下拉刷新**：下拉后重新取一批人物卡片，专题文章一并更新；正在搜索时按当前关键词重搜。

### 3.2 人物详情：一个人五个面

详情页底部固定五个标签，其中档案、年表、关系在本页内切换，世系、足迹为独立页面：

1. **档案**：深色身份头展示姓名、拼音、国家与生卒、身份标签、三项统计与收藏按钮；下方是「生平介绍」，长篇可折叠；再往下是「档案与延伸」，分段为基础档案（17 行字段）、作品与成果、纪念与遗产、时代背景、相关文章。没有内容的段落显示「本站暂未收录更多档案」，不空占位。
2. **年表**：按阶段分卡，每张卡头写阶段序号、阶段名与起止年；有确切年份的事件按年排列。仅标注朝代的条目收进「朝代区间带」，用一条带表示所处朝代区间，不假装有确切年份；「未详」「不详」类条目单独放在年表末尾。年表顶部有「双人生命线」入口，仅在人物属于精选且生卒都可计算时出现。
3. **关系**：默认「图谱」，可切「列表」。图谱支持拖拽、双指缩放、点击节点切换中心人物；列表按关系分类逐条列出，点人物继续进入其档案。首次进入先显示骨架屏，数据回来再填充。
4. **世系**：上下代直系主轴，默认「父系 + 母系」全显示，可切成「只看父系」；每代开头是代次头，点一下收起或展开整代；点树上的名字可换中心人物，上方「返回」回到上一位。
5. **足迹**：见 3.3。

### 3.3 人物足迹地图

- 用微信原生地图组件渲染一生到过的站点，站点分诞生、终老、途经、档案、大区五类图例，站点之间用折线连接。
- 两种浏览方式：「单卡跟随」同屏一张事件卡，跟着圆点逐站走；「全部展开」一次铺开所有站点，点任一站看该站事件。
- 时间轴支持拖动刻度换站、‹ › 逐站前后走、播放键自动回放；「全部 N 卡」打开纵向卡片列表。
- 部分增值能力（更多底图、完整轨迹、全览）需观看激励视频解锁；站点很少的人物整档免解锁。

### 3.4 年份查询（七历对照）

- **输入规则**：公元数字（如 1279）、公元前（写「前200」）、年号加年数（如「祥兴二年」）、只写朝代名均可。只写朝代名时，先给开国、鼎盛、亡国三个参照年；只写年号名时列出同名候选，需再补第几年。
- **输出**：一次给出七套纪年对照——年号纪年、干支、公元、伊斯兰历、佛历、民国纪年、日本年号，并标注换算说明。
- **辅助**：无结果时页面提供三张示例卡（公元数字、年号加年数、朝代名），点示例直接带入查询；结果页有图例说明各历口径。
- 口径提示写在页面上：换算属工具性推算，史事年份仍以正史本纪为准。

### 3.5 大事年表

- 一条只占一行：年份 + 提要；点按展开正文，纪事给概要，战役给战果、兵力与背景；再点收起，列表不跳位置。
- 搜索支持年份（1937、前221）、人物名与事件名（如「赤壁」）；命中后列表只留相关条目。
- 年代尺可按年份横向滑动换年代；右侧「筛选」可按分类收窄、只看里程碑，或直接跳到某一年。年代尺只影响视线范围，不清空搜索词。

### 3.6 朝代时间轴与历代帝王

- **朝代时间轴**：从先秦到晚清分八段，点一段直接跳到该段，滚动时高亮跟随当前段。一段内一行一个朝代，右侧写起止年与时长；行末带 ▸ 的朝代可展开子项（如周展开为西周、东周、春秋、战国）；行末为 › 的朝代点开底部半屏，显示起止年、都城与沿革简介。
- **历代帝王**：从先秦到元明清分六段，段头写起止年与帝王人数；十六国、五代十国先列政权，点政权名再展开该政权的帝王。点帝王行弹半屏简介：生卒、在位、年号与一段生平；底部「查看完整人物档案」进入人物页。右上角「朝代」可一次列出全部朝代，点哪个跳哪个。

### 3.7 六度空间：两个人之间的最短关系路径

- 起点、终点分别输入姓名，等联想候选出现后点选；同名人物会并列列出，按朝代与性别区分，选错可点「×」清空重填。
- 查询结果按度数从少到多排列，一次最多返回 3 条候选路径；路径行用手风琴展示，行摘要写「① 经杨妃」这类中间人提示，展开看完整链路，每个节点可继续点进人物档案。
- 页面内可打开关系小图，用 Canvas 绘制完整路径，支持缩放与拖动；缩放低于 0.9 倍时自动隐藏副行（朝代、路径号），避免文字挤在一起。
- **分享卡**：取当前结果中最短的一条路径，用 Canvas 2D 一次性绘制后导出为图片（逻辑尺寸 335×566，3 倍绘制导出 1005×1698），弹层内只显示图片，可保存到相册；绘制失败有重试入口。

### 3.8 双人生命线

- 入口在人物详情年表顶部，只在精选人物且生卒年都可计算时出现；进入后选另一位生卒可算的人物。
- **A 双轨年表（默认）**：两条生命线上下排列，标出并存区间、年龄差、晚走年数；事件卡标题写「同在这 N 年里的 M 件事」，没有重叠时如实说明。
- **B 三段人生**：按真实区间切「只有他 / 同在一世 / 只剩他」三段，卡片文案只取库内事件；年份不全时明确提示无法切分，仍可在双轨年表看各自的开口线。
- **分享卡**：C 版式，Canvas 2D 绘制 1080×1920 后保存相册；并存区间算不出时提示「暂不能生成分享卡」，不生成空卡。

### 3.9 平行时空与「这一年，谁在场」

**平行时空**

- 两种定锚方式：「选人物」用某人的出生之年（生年不详改用卒年）作锚点；「选年份」直接输入一年或点快捷年份。
- 结果页默认「平行双流」：左列中土编年，右列域外同期人物与事件，域外默认取锚点前后 25 年，选人物时改用其生卒区间，锚点卡上注明容差口径。
- 可切「世界地图」，按地理分布看同期文明，点圆点或标签看该文明的同期记载；长按任意卡片弹出人物或事件简介；右上「换一个」回到选择区。
- 不确定从谁开始时，可点六张热门人物方牌，直接用其出生年进入结果。

**这一年，谁在场**（平行时空结果页的二级页）

- 把该年人物记载分为三幕：**登场**为该年出生的人，**在场**为该年有任职、登第或要事记载的人，**离场**为该年去世的人。
- 每幕默认只列 6–8 人，点「展开」到该年全部前 40 条；某幕无人时显示空提示，不占位。
- 「在场」再按三档切换视角：与要事相关（本年事件主角）、按知名度（收录的精选人物）、按身份（本年在任或登第的人）；某档本年没有数据时不出现，记载少的年份可能只剩一档。

### 3.10 职官别名与地名查询

- **职官别名**：可按别名、职能或类别检索古代官职别称；提供热词快捷入口（如「太傅」）、类别浏览、前缀联想；结果可按朝代与范围筛选，词条展示释义、朝代、对应官职与注释，支持复制。数据底本为《中国历代职官别名大辞典》的解析整理。
- **地名查询**：点击地图上的省份逐级下钻到县，也可点热门地名或直接搜索省、市、县、乡镇名；结果给古今地名对照。查不到时页面提示换更短写法（如写「定襄」比「定襄县」更容易命中）。
- 行政区划边界通过服务端转发的 GeoJSON 获取，服务端缓存 7 天，避免每次进页面重新拉取。

### 3.11 节日文化

- 深色头四块磁贴给出总量：节令 142、民俗 162、民族 48、地方 29，合计 381 条。
- 四类 tab 可单独筛选，再点一次退回综合视图；主体是 12 个月竖向长卷，月头互斥展开（同时只开一个月）。
- 展开后按当前分类只渲染对应段落：节令行、民俗双列格、民族条、地方行；核心传统节日（春节、元宵、清明、端午、七夕、中秋、重阳、腊八、除夕等）在民俗格内高亮。
- 顶部十二月方块条随内容滚走，滚动越过深色头后浮出窄标题条；点方块条切月并定位。

### 3.12 文章专题与特别专题

- **文章专题 5 个**：历史人物、冷知识、国内之最、节日文化、历代战役，合计 98 篇（截至 2026 年 11 月专题页统计口径）。专题行显示序号、名称、篇数、最近更新日期；展开后列出前 3 条篇目与「进入专题」。
- **特别专题 4 个**：铭记历史（1931—1945 重大事件时间线与历史档案）、解放战争、历代条约、节日文化。特别专题没有篇目列表，行尾标「独立专题站」，点击直接进入对应专题页。
- **两种呈现形态**：摘要行手风琴（组内单开）与两列封面墙（单条横展），可在「我的 → 设置 → 专题页」切换；同时可设默认收起或默认展开首条。偏好只存本机，键名带版本号，读取失败回落到默认值，切换后立即生效，不需要重启。
- **文章阅读**：文章详情支持正文阅读、点赞与收藏、上一篇/下一篇与相关阅读；文章中关联的人物可直接跳转人物档案。专题列表接口提供 `lite` 轻量版，不返回正文，正文按单篇取，减少首屏流量。

### 3.13 实时看板

- **规模磁贴**：人物总数、关系总数、作品数、年表事件数四项，另附覆盖率与人均关系数。
- **数据体检**：7 项字段填充率，按高低排序，低于 50% 的项标出。
- **史料支撑**：累计来源条数、覆盖人数、三类来源分布、主要史籍 TOP2。
- **结构画像**：朝代分布（默认 9 行，可展开全部 60 个）、性别构成、身份词云（默认 10 个，可展开 40 个）。
- **影响力与极值**：影响力指数榜（浏览 + 关系×10 + 作品×5，分项摊开）、全库之最 5 项与开国君主数。
- **动态**：优先展示真实更新记录（新增收录 / 更新资料 / 关系更新）；没有近期记录时，改用累计事实并明确标为「全库累计」，不把累计量伪装成刚发生。
- 页面显示快照生成时间，支持手动刷新；服务端正在计算时进入轮询，不误报为网络错误。

### 3.14 账号与运营功能

- **登录注册**：账号密码登录、手机号登录/注册，支持昵称与手机号占用校验、密保问题、修改密码、绑定手机号。
- **收藏与历史**：人物收藏、浏览历史、文章点赞收藏；「我的」页可查看与管理。
- **站内信**：未读红点、消息列表、已读标记。
- **意见反馈**：提交与历史两个页签；类型可选建议、BUG、内容、其他、注销账号；内容 1–2000 字，截图最多 1 张；只有选「注销账号」时联系方式必填邮箱。
- **邮件联系**：两个收件邮箱可选，主题可留空（自动用默认标题），内容必填且有实时计数；同一网络每小时最多 3 封，服务端限流。
- **账号注销**：提交后进入 7 天冷静期，冷静期内可撤回；注销结果通过邮件告知。
- **设置**：专题页风格与默认展开状态；「关于世慧屋」展示版本与备案信息；隐私政策与用户协议独立页。
- **使用指南**：常驻「我的」页，列出全部已接入引导及完成状态，可逐项重看。

## 五、数据来源与真实性原则

### 5.1 来源类型

- **正史与编年体**：二十四史及《清史稿》等列传、本纪、志表，以及编年体史书的纪事。
- **地方志与地理总志**：用于补籍贯、仕履、地方人物与地名沿革。
- **墓志汇编、碑刻与家谱资料**：用于补生卒、世系、婚姻关系。
- **人名辞典与人物志**：《中国人名大辞典》等工具书条目，用于交叉核对姓名、字号、籍贯与身份。
- **职官工具书**：《中国历代职官别名大辞典》解析整理为职官别名数据。
- **公开古籍文本与已整理出版物**：用于生平叙述与事件定年。

产品不使用任何外部人物数据库作为数据来源，也不把第三方数据库的标识或链接写入人物档案。

### 5.2 真实性原则

1. **不确定就不写。** 缺生卒、缺籍贯、缺仕履的条目，字段留空或标「待补」，不用推测值填充；模型生成或整理的文字必须能在来源中找到依据。
2. **缺字段统一标待补。** 截至 2026-11-16，本地库 599 条、线上库 265 条人物档案处于「待补」状态，原因分「缺乏可区分线索」与「来源不足」两类；待补说明写在状态字段，不塞进生平正文冒充史实。
3. **错误记录定期核查修正。** 以 2026 年 11 月为例：本地 3,336 条、线上 1,210 条人物生平中的内部标记与来源引用被清除；本地 381 条、线上 320 条完成正文回补、重写与模板化内容清理；对 359 条待补条目做联网查证，本地定案写库 38 条、线上 14 条，其余列入待复核或维持待补。
4. **生卒与关系冲突不硬改。** 父子代际颠倒、卒年后出生、生卒倒挂、关系闭环等问题，必须有明确文献支撑才修改；仅有逻辑冲突的条目列入待考清单。截至 2026-11-16，此类待考条目剩余 647 条（本地口径），未做猜测性修改。
5. **改动可追溯。** 每次批量修改前做数据库一致性备份（`VACUUM INTO`），脚本默认 dry-run、加 `--apply` 才落库，幂等可重跑；改动账本记录改前值、改后值、判据与来源。仓库 `docs/` 下保留分轮报告与总账。
6. **本地与线上分别处理。** 两边原文不一致时就地处理，不用本地覆盖线上；索引表在改动后重建，并核对前后计数。

## 六、体验设计要点

### 6.1 全站使用引导

- **三种形态**：分步遮罩（layer，带挖孔高亮与箭头卡片）、单条气泡（bubble）、页面内空态卡（empty）。分步遮罩支持多目标并集挖孔、目标在视口外先滚动到位、按目标方向自动翻转卡片。
- **覆盖范围**：16 个引导入口，覆盖 15 个页面——全站新手引导、六度空间、职官别名、地名查询、大事年表、年份查询、朝代时间轴、历代帝王、意见反馈、邮件联系、平行时空（选择区与结果页各一套）、这一年谁在场、人物详情、世系、人物足迹。
- **处理「引导里点不到」的状态**：需要展开才可见的面板（如下拉、底部半屏、年份切换态）用静态复刻示意，不要求用户在遮罩下真实点击；关系页、年表页这类需要先切标签的目标，由引导先替用户切过去再测量真实节点。
- **条件目标可跳过**：标记为 optional 的步骤在目标不存在时直接跳过，不把用户停在「没有孔的遮罩」上；最后一步缺失则直接结束。
- **进度与重看**：进度只用一个本地存储键，键名带版本号；「跳过」与「看完」都记为完成，中断不记，下次重来。重看入口在「我的 → 使用指南」，只留一次性标记，由目标页消费，10 分钟过期，不改动完成记录。

### 6.2 分包与加载性能

- **分包策略**：主包保留首页、专题列表、查询、我的、文章、节日、朝代、帝王、职官别名、看板、六度、平行时空 12 页；详情、双人、世系、图谱、足迹、专题站、时间轴、地名、账号、管理端拆为 10 个分包，避免首包过大。
- **预下载**：配置 18 条 `preloadRule`，在 Wi-Fi 下从首页预下载详情与专题分包、从详情预下载世系/足迹/图谱分包、从查询预下载详情/时间轴/地名/平行时空分包，减少二次跳转等待。
- **按需注入**：开启 `lazyCodeLoading: "requiredComponents"`，只注入当前页面用到的组件。
- **缓存与兜底**：人物池与首页卡片有本地缓存，弱网时先显示旧数据再更新；统计看板使用服务端快照，页面显示快照生成时间，避免把旧数据当实时数据。
- **接口分层**：专题列表提供 `lite` 版本，不返回正文；正文按单篇取；人物批量接口单次上限 200，减少关系页多次请求。

### 6.3 底部导航与页面结构

- 自定义 tabBar 四项：首页、专题、查询、我的；选中态用朱红，未选中为墨褐。
- 「查询」页把 8 个工具按用途分四组：按时间查（大事年表、年份查询、历代帝王、平行时空）、人物与关系（六度空间）、名物检索（职官别名、地名查询）、数据概览（实时看板）。组内用两列卡片与整宽行混排，工具名与副标题保持稳定，不随版本改名。
- 人物详情用底部五标签替代返回式层级：档案、年表、关系页内切换，世系、足迹跳独立页；切换不丢失当前人物上下文。
- 「最近查询」仅在有记录时渲染，点击历史词回到首页执行检索；不需要位置权限，不申请无关的隐私接口。

### 6.4 分享卡

- 六度空间与双人生命线都能生成分享卡，均为 Canvas 2D 一次性绘制后导出图片，弹层内只放 `<image>`，不把原生 canvas 直接放在弹层里预览。
- 这样处理的原因是：原生 canvas 图层与弹层布局在刚挂载时容易不同步，直接预览会出现整块错位、按钮被顶出屏幕；先导出图片可以规避。
- 分享卡使用库内原词，不做美化；超过 8 字的关系长句与把姓名误当关系词的脏数据会截断；二维码加载失败时降级为占位框，不展示假码。
- 生成过程显示遮罩，失败提供重试；底部操作按钮固定在滚动区外。

### 6.5 空态与降级

- 无事件、无关系、无足迹、无专题文章均有独立空态文案，不用「暂无数据」一句话糊过去。
- 接口失败时保留页面骨架与重试入口；统计看板服务端计算中显示计算态并自动轮询，不误报网络错误。
- 人物头像缺失时用姓名首字占位；朝代背景图缺失时回落为纯色底。

## 七、技术架构

### 7.1 客户端

- **框架**：微信小程序原生框架（WXML / WXSS / JavaScript），不使用第三方 UI 框架；自定义 tabBar；42 个页面按 10 个分包组织。
- **图形渲染**：
  - 关系图谱使用 Canvas 渲染：实例化 ECharts 的 graph 系列，支持力导向布局、拖拽、缩放与节点点击换中心。
  - 六度空间的路径小图与分享卡使用 Canvas 2D 直接绘制；分享卡绘制完成后通过 `wx.canvasToTempFilePath` 导出图片。
  - 足迹地图使用微信原生 `<map>` 组件，站点用 marker、路线用 polyline。
- **本地能力**：本地存储用于引导进度、专题页偏好、最近查询、人物池缓存；偏好键名带版本号，读取失败回落默认值。

### 7.2 服务端

- **运行时**：Node.js + Express。
- **数据库**：SQLite，使用 better-sqlite3 同步访问；核心表包括 `figures`、`figure_relations`、`event_timeline`、`figure_alias`、`figure_book_sources`、`figure_noindex`、`official_aliases` 及用户、收藏、历史、反馈、消息等表。
- **接口模块**：人物（查询、联想、批量、关系、世系、六度路径、热门）、年表（meta、按年、按类分页、检索、总览）、年份查询、朝代与帝王、文章与专题、职官别名、地名与 GeoJSON 转发、统计（实时快照、浏览上报、近期动态）、反馈与邮件、认证与用户中心、客户端错误上报。
- **缓存**：GET 接口缓存；统计快照按小时复用并在响应信封返回 `snapshotAt`；近期动态 30 秒缓存；GeoJSON 7 天缓存；六度路径结果缓存 10 分钟。
- **部署**：PM2 守护 Node 进程，Nginx 反向代理与静态资源服务，HTTPS 对外；数据库与前端产物分别部署，部署脚本支持前端、后端、数据三类。

### 7.3 数据生产链路

史料与书籍文本 → 解析脚本抽取人物、事件、关系 → 人工核查与补全 → 幂等脚本落库 → 重建 `event_timeline` 索引 → 备份与账本归档 → 小程序端通过 API 读取。

| 族谱、家谱类网站         | 单姓世系深、支系完整      | 跨姓氏、跨朝代的关系网络；世系与人物档案、年表联动；不局限于单一宗族                 | 单一家族的世代深度不及专业族谱站            |

## 九、已知局限与后续规划

### 9.1 已知局限

1. **部分人物档案不完整。** 本地 599 条、线上 265 条处于「待补」，只有姓名、朝代等少量字段；这些条目仍可被检索，但详情页会明确提示待补，不编造生平。
2. **部分生卒与关系仍待考。** 647 条（本地口径）存在生卒倒挂、代际冲突、同名异人或来源矛盾，已列入待考清单；在拿到明确文献前不改动。
3. **数据规模小于大型学术库。** 57.3 万（本地）/ 53.4 万（线上）人物、79.4 万/74.0 万关系边，覆盖面仍以正史与常见工具书所载人物为主；先秦、少数民族政权、近现代人物的完整度不均衡。
4. **年表定年精度不一。** 一部分条目只能定到朝代，页面用「朝代区间带」如实呈现，不给出假精确年份；「未详」类条目单独排列。
5. **关系是「已收录关系」，不是完整社交网络。** 图谱展示的是库内已整理的关系边，文献有记载但尚未整理的关系不会出现；关系缺失不等于历史上没有交集。
6. **域外人物与事件覆盖有限。** 平行时空的域外部分为独立的同期参照数据集，重点在「同年有谁」，不是完整的世界史年表。
7. **部分页面真机验证仍在进行。** 开发阶段发现的基础库报错已定位为工程配置问题并修正，仍需在更多机型与微信版本上复测；分享卡依赖 Canvas 与相册权限，低端机导出耗时更长。
8. **部分增值能力需观看激励视频。** 足迹页的更多底图、完整轨迹与全览属于运营设计，不影响核心站点浏览。
9. **内容更新依赖人工核查。** 数据修正按批次推进，不是实时自动更新；新收录与修正以仓库账本与线上快照为准。

### 9.2 后续规划

1. **补全待补档案。** 按待补清单中的线索列逐条查证，查不到的维持待补，不用模板文字填满。
2. **提高年表定年精度。** 对仅标朝代的条目做小范围、可溯源的定年补全；无法定年的继续用区间带呈现。
3. **扩展域外同期数据。** 增加域外人物与事件的覆盖，改善平行时空右列的密度与可读性。
4. **优化性能与兼容性。** 继续压缩首屏请求与分包体积，补齐低端机、深色模式与不同微信版本的回归测试。
5. **完善分享与传播。** 在现有两张分享卡的基础上，补充失败重试与保存引导，观察分享路径的实际使用情况后再决定是否扩展。
